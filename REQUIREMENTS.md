# Case-study implementation status

Source: *AI-Powered Intelligent Railway Travel & Autonomous AI Governance Platform*, 7-page student case study. A working demonstration is not a production railway service.

| Case-study requirement | Status | What the project does | Remaining work |
|---|---|---|---|
| Large railway data foundation | Implemented for offline research | Imports 326,643 fare rows and 38,428,703 delay rows from two public Kaggle datasets; validates, indexes, documents exclusions; includes 24 nationwide station aliases, station stop counts, and production PostgreSQL foundation schema | Verify publisher provenance and acquire official operational feeds |
| Journey planner and recommendations | Partial | Passenger route search covers historical routes, classes, budgets, maximum scheduled duration, and 4 sorting modes including multi-criteria balanced recommendation score (fare + duration + historical delay risk); natural language query parsing; timetable-only matches with held-out-tested distance estimates; anonymous usefulness feedback | Current schedules, travel-date service days, availability, preference learning, validated ranking evaluation |
| Delay prediction and disruption response | Partial | Train/station empirical delay shrinkage model with time-separated test (24.66m MAE); delay risk categorization (punctual, moderate, severe); Disruption Rescue Agent evaluates deadline violations and provides structured alternative justification | Real-time train positions, live disruptions, calibrated uncertainty, proactive alerts |
| WL/RAC confirmation | Demonstration only | Admin synthetic prototype with Beta(1,1) smoothing; added probabilistic Brier score and bucketed calibration evaluation (WL 1-5, 6-15, 16+); reviewed 30,000-row synthetic Kaggle dataset and documented why it was excluded from passenger predictions (0 confirmed outcomes) | Real booking and final-chart outcomes; calibrated confidence intervals |
| Fare prediction and demand | Historical estimate only | Observed October 2023 fares searchable in SQLite; missing route fares estimated via class-specific distance regression tested on held-out trains; synthetic dynamic pricing scenario with booking lead-time trajectory (30d, 15d, 7d, 1d) | Estimate error remains material, train class availability is unverified, and multiple dated snapshots/demand labels are needed for future-fare prediction; current quotes require an official feed |
| Live PNR and seat availability | PNR integration ready; seats unavailable | Server-side RapidAPI PNR adapter supports the selected provider's GET path when the user configures host and key; rejects provider `success: false` responses. Fictional sample PNRs are separate. Route and seat adapters remain unavailable without their own documented endpoints. Historical data marks seats as unverified | Provider subscription, valid current PNR test, usage-rights review; separate verified fare/seat endpoints and response mapping |
| Customer support | Demonstration only | Grounded bilingual (English/Hindi) policy answers across 6 core railway domains (refund, cancellation, Tatkal timings/rules, RAC berth entitlement, luggage allowances, senior citizen concessions) + synthetic PNR; strictly abstains on ungrounded queries; tracked in governance with hallucination control / abstention rate metric | Official current policy, PNR and refund services; measured multilingual quality |
| Booking approval and transactions | Partial | Two-phase booking preview requiring passenger details (name, age, berth preference) and explicit consent check before saving itinerary; status clearly marked preview only; no funds charged and no live railway booking performed | Official booking and payment tools with consent, confirmation and failure handling |
| Multi-agent orchestration | Implemented simulation | Formalized 5 specialized agents (`TravelPlannerAgent`, `PredictionAgent`, `SupervisorAgent`, `RescueAgent`, `GovernanceAgent`) with execution trace (`orchestration_trail`) logged and presented in scenario lab | Independent distributed agents with network RPC contracts and end-to-end evaluation |
| Fraud/bot detection | Demonstration only | Rule-based triage scoring incorporating booking frequency, failed login spikes, payment mismatch, abnormal query velocity (bot scrapers), and sub-3-second automated form submission (Tatkal scripts); outputs actionable risk tier for human review | Real event stream, labels, investigation workflow and false-positive evaluation |
| Autonomous AI governance | Implemented demonstration | Control room monitoring model inventory, data quality exclusions, holdout MAE, confirmation Brier score & calibration, support hallucination abstention rate, request latency p95 against 1000ms SLO, voluntary recommendation feedback, drift detection, and candidate model evaluation with approval gate and rollback | All-model real-time drift, bias, hallucination, resource monitoring, validated root cause and deployment automation |
| Security, privacy, scale | Partial local demo | Local binding (127.0.0.1), scrypt password hashing, session tokens, failed login rate limit (5 attempts / 15 min), PII removal from audit logs, HTTP security headers (`nosniff`, `DENY`, CSP, `Referrer-Policy`), comprehensive PostgreSQL target schema for national scaling | HTTPS, durable sessions, broader rate limits, privacy program, load testing, resilience, compliance review |

## Data sources and limits

- [Indian Railways Schedule-Prices-Availability Data](https://www.kaggle.com/datasets/bhavyarajdev/indian-railways-schedule-prices-availability-data), Apache 2.0, publisher-reported October 2023 snapshot. The app uses schedule and fare fields. It intentionally does **not** display 2023 availability as current seats.
- [Indian Railways - Delay Dataset](https://www.kaggle.com/datasets/rxydenxd/indian-railways-delay-dataset), MIT, publisher-reported station-level scraped observations from February 2025 to February 2026. The publisher's real-world provenance has not been independently verified.
- [Indian Railway Ticket Confirmation](https://www.kaggle.com/datasets/aaryananil/indian-railway-ticket-confirmation), MIT, explicitly synthetic. Reviewed, but not used for passenger predictions: none of 10,053 usable wait-list rows had a confirmed final outcome. The `Current Status` field also reveals much of the target, so using it would risk leakage.

Exact imported and test counts, exclusions and delay test error are in `data/kaggle_report.json` and displayed in the admin governance page. Running `import_kaggle.py` with the three original ZIP files rebuilds the catalog and model.
